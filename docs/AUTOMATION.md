# Как улучшать скрипт автоматически

Проверки запускаются одной командой, а выпуск новой версии — тоже одной.
Всё, что раньше делалось руками (поднять версию, обновить копии файла, коммит,
push, комментарий в PR), делает `tools/release.sh`.

## 1. Одна команда — все проверки

```bash
./tools/check_all.sh
```

Что проверяется (ровно то, что валит игру, а не абстрактная «красота»):

| # | Проверка | Какой баг ловит |
|---|----------|-----------------|
| 1 | `tools/luau_check.py` — компилятор Luau из Roblox | синтаксис, `+=` у константы, лимит 200 локалей в функции |
| 2 | `tools/declared_before_use.py` | `function CH.apply(...)` без `CH = {}` — падение **при загрузке** (это и был баг 4.6.1) |
| 3 | `tools/limit_locals.py` | превышение лимита локальных переменных |
| 4 | `python3 -m unittest discover -s tests` | 135 тестов: настройки, UI, справка, порядок объявлений |
| 5 | сверка версии | в шапке `vX` и `GLB.BUILD` не расходятся |

Зелёный вывод: `ВСЁ ЗЕЛЁНОЕ: скрипт собирается, загружается и проходит тесты`.

## 2. Выпуск новой версии одной командой

```bash
./tools/release.sh 4.6.3 "что изменилось"
```

Скрипт сам: прогоняет проверки → отказывается выпускать при провале →
поднимает `GLB.BUILD` → дописывает строку в шапку-историю → обновляет
`loadstring.lua` (ссылка для телефона) → коммит → push → комментарий в PR
со ссылкой на конкретный коммит.

## 3. Защита от «не работает»

`.git/hooks/pre-commit` не даёт закоммитить `Enkaisy_Combined_UI_v4_2.lua`,
если проверки не зелёные. Можно поставить и после клонирования:

```bash
cp tools/git-hooks/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```

## 4. CI на GitHub

`.github/workflows/checks.yml` запускает те же проверки на каждый push и PR.
**Сейчас не работает:** у интеграции, под которой я работаю, нет прав на
включение Actions (`403 Resource not accessible by integration`). Включается
руками: **Settings → Actions → General → Allow all actions**.

После включения каждая ветка и PR будут автоматически помечаться зелёным или
красным, и в `main` физически не попадёт скрипт, который не компилируется.

## Что автоматизировать дальше (по убыванию пользы)

1. **Проверка в самом Roblox.** Сейчас проверки статические. Настоящая страховка —
   тестовый плейс: executor + второй аккаунт, скрипт сам себя запускает и
   присылает скриншот. Даёт ответ «ESP реально работает», а не «код выглядит верно».
2. **Скриншот-тесты интерфейса.** В репозитории уже есть `tools/*-preview.html`;
   можно рендерить их в PNG через headless-браузер и сравнивать с эталоном —
   тогда сломанная вёрстка вкладки видна без запуска игры.
3. **Автотест «каждая настройка что-то меняет»** — расширение идеи
   `tests/test_chams_settings.py` на все вкладки: для каждого ключа `CFG.*`
   проверить, что он читается в коде отрисовки.
4. **Генерация changelog** из сообщений коммитов в `CHANGELOG.md` — чтобы история
   в шапке файла не разрасталась.
5. **Релиз в GitHub Releases** (когда появится право на `uploads.github.com`) —
   файл `.lua` будет скачиваться одной ссылкой без страницы-обёртки.
